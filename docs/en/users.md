# People and music access

Only an administrator can add accounts and grant libraries. Use a separate account for each person: favourites, play history, themes and family records belong to that account.

1. Open the sidebar → **Users** → **Create**.
2. Enter a unique username, display name and a strong unique password. Email is optional. Leave **Administrator** off for ordinary listeners.
3. Select only the libraries this person should hear. On a new public installation no library is selected automatically. Save.
4. Sign in in a private browser window as that member. Confirm that approved albums appear and other libraries do not.
5. To change access, edit the user and their libraries. In public mode an administrator can remove every library to suspend music access without deleting the account. Existing private installation policies may differ.

An administrator can access every library and administer the server. Do not use the administrator role simply to share a shelf. Sharing a family record does not grant access to its referenced music. Library removal can therefore make an album in a shared record unavailable.

Use [Kids accounts](features/kids.md) for protected children. Do not turn a protected account into a normal account to bypass its restrictions. Before deleting a person, export their history where appropriate and make a [backup](backups.md); deletion is not an access pause.

If the member sees an empty library, check their library grants, source connection and scan status. Test with a fresh sign-in after a permission change. Keep setup tokens, passwords and session tokens out of screenshots and issues.
