# Собственное развёртывание в Bunny Magic Containers

Это необязательный удалённый запуск в вашем аккаунте. Приложение бесплатно; условия оплаты Bunny, registry и storage относятся к вам. Сначала пройдите [локальную установку](docker.md) и [проверку восстановления](../backups.md). Общего демосервера и реестра с чужой конфигурацией нет.

## Подготовка на компьютере

1. Соберите принятые исходники в Docker Desktop: `docker build --platform linux/amd64 -f Dockerfile.family -t YOUR_PRIVATE_IMAGE:YOUR_IMMUTABLE_TAG .`. Замените пример своим существующим приватным registry/repository.
2. Войдите поддерживаемым существующим способом, отправьте образ и проверьте remote manifest digest через Docker. Сохраните точный образ/digest и соответствующий релиз исходников.
3. Magic Containers должен иметь официальный registry binding и поддерживаемую авторизацию pull. Локальный вход Docker Desktop сам по себе не разрешает Bunny получать образ. Не открывайте временный публичный registry, не используйте неподдерживаемые endpoints и не предполагайте прямой импорт локального OCI-архива. Если существующий credential не подходит для pull, зафиксируйте ограничение до деплоя.

## Настройка своего экземпляра

Используйте [официальное руководство](https://bunny.net/docs/magic-containers) и dashboard. Укажите точный приватный образ, одну реплику и persistent volume **5 GB**, смонтированный в `/data`; HTTP-порт контейнера **4533**, публичный endpoint с HTTPS. У каждой реплики собственный том: SQLite нельзя масштабировать так, будто реплики имеют общую базу. См. [объяснение persistent volumes](https://bunny.net/blog/magic-containers-now-supports-persistent-volumes-storage-that-survives-restarts-and-redeployments/).

Задайте `FMH_INSTALL_MODE=PUBLIC_SELF_HOST`. Оставьте sharing, внешние сервисы и insights выключенными без явной необходимости. Если приватно прочитать `/data/setup-token` невозможно, поместите случайный URL-safe `FMH_SETUP_TOKEN` длиной 32–96 символов в secret store платформы. Откройте свой endpoint, введите токен и создайте собственные реквизиты администратора. После этого удалите необязательный setup secret и перезапустите. Не устанавливайте чужую БД и предсозданные аккаунты.

Удалённый контейнер не видит папку ноутбука. Настройте свою [Bunny-библиотеку](../integrations/bunny.md) или поддерживаемый внешний источник. Mac Sync нужен только при выборе загрузки в Bunny. Секреты храните на сервере. Необязательные онлайн-копии требуют `FMH_BUNNY_BACKUPS=true`, приватного write credential и отдельно сохранённого ключа шифрования; см. [ограничения копий](../backups.md).

## Приёмка и обновление

Проверьте HTTPS `/ping`, вход администратора и участника, явные права, MP3/FLAC и Range. Для тестов создавайте только синтетические семейные записи. Храните полную зашифрованную копию SQLite, KV/пакетов плагинов и вложений. Перед обновлением используйте официальный полный export/restore тома и отдельно проверьте прежний образ с соответствующим снимком. Наличие API списка томов не доказывает доступ к их файлам; SQLite-only копия не доказывает полный откат. Если механизма нет, сохраните работающий сервер и зафиксируйте blocker обновления.

Для обновления образа не удаляйте/пересоздавайте том, пользователей и секреты. Сохраняйте прежние replica/region, настройте health check и проверьте фактически развёрнутый digest.
