# Безопасность и приватность

Сервер хранит личную историю прослушивания, письма, воспоминания, возможно фотографии и голосовые вложения. Защитите `/data`, копии и KV-хранилища плагинов. Для удалённого входа используйте HTTPS, уникальные пароли и обычные аккаунты слушателей. Пока доверенный HTTPS-прокси не настроен, оставьте Docker доступным только через loopback.

Первый запуск публичной версии требует случайный setup-token с вашего сервера. Это не стандартный пароль и не способ последующего входа. После создания администратора повторное создание первого администратора запрещено. Перезапуск удаляет файл токена при наличии аккаунтов. Не публикуйте его в обращениях.

Новые участники публичной установки не получают библиотеки автоматически. Администратор выдаёт доступ явно. Семейная запись ссылается на музыку, но не открывает доступ к аудио. Детские аккаунты дополнительно ограничены. Перед отправкой письма или публикацией воспоминания проверьте получателей. Legacy-экспорт содержит личные сведения и требует такой же защиты, как резервная копия.

Ключи и пароли источников храните в секретной конфигурации сервера, не в браузерных формах, Git и открытых логах. Форма подключения ссылается на имя переменной секрета. Не отключайте TLS/SSH-проверку и защиту частной сети. Удаление конфигурации источника не требует удаления музыки.

Внешние метаданные и тексты необязательны. Включённый плагин отправляет запросы и выбранные метаданные заявленным провайдерам. Проверяйте разрешения и фиксируйте версии. Публичный Docker-профиль по умолчанию отключает внешние сервисы, sharing, Gravatar и сбор insights; явно включённые плагины имеют собственное сетевое поведение.

Сообщайте об уязвимости закрыто по [SECURITY.md](../../SECURITY.md), используя синтетический пример. Не прикладывайте реальные токены, музыку, адреса, SQLite и семейные записи. Открытая лицензия кода не делает данные вашего сервера публичными.
