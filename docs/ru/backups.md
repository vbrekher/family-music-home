# Резервное копирование и восстановление

[English](../en/backups.md) · [Русский](backups.md)

Личный Legacy ZIP не является резервной копией сервера и не зашифрован. Отдельно храните зашифрованную серверную копию, ключ расшифровки, оригинальную музыку и секреты сервера. Без прежних ключей шифрования паролей/сервера восстановленная установка может не открыть сохранённые credentials.

## Какую копию выбрать

| Копия | Что содержит | Чего не содержит |
|---|---|---|
| Legacy ZIP | Разрешённую вам историю JSON/Markdown/M3U и выбранные вложения | Оригинальную музыку, личные записи других взрослых, шифрование, полное восстановление сервера |
| Онлайн NDBACK01/02 | WAL-safe снимок SQLite; NDBACK02 — также связанные приватные вложения | Отдельные KV-базы плагинов, установленные пакеты плагинов, оригинальную музыку, секреты окружения |
| FMHFULL1 остановленного тома | Данные приложения, включая пакеты/KV-базы плагинов и приватные вложения; без восстанавливаемого root cache | Музыку за пределами /data, секреты окружения сервера, внешнее хранилище |

Зашифрованные форматы используют аутентифицированное AES-256-GCM. Ключ из 32 байтов (64 шестнадцатеричных символа) храните отдельно в менеджере паролей или Keychain. Не помещайте его в Git issue, скриншоты или аргументы команды. Хотя бы одну зашифрованную копию храните отдельно от тома приложения.

## Полная копия локального Docker

1. До остановки запишите точный образ и контейнер. Создайте защищённую выходную папку:

   ```sh
   FMH_CONTAINER=$(docker compose -f compose.family.yml ps -q music)
   FMH_IMAGE=$(docker inspect "$FMH_CONTAINER" --format '{{.Image}}')
   mkdir -p backups
   chmod 700 backups
   docker compose -f compose.family.yml stop music
   ```

2. При остановленном приложении запустите помощник. Он запросит ключ без отображения ввода. Каждый раз выбирайте новое имя архива:

   ```sh
   docker run --rm -it --volumes-from "$FMH_CONTAINER":ro \
     -v "$PWD/backups:/backup" --entrypoint python "$FMH_IMAGE" \
     /app/bunny/full_backup.py backup /data /backup/family-full.enc
   docker compose -f compose.family.yml start music
   ```

3. Проверьте сообщение об успехе и сохраните image ID в приватной записи о копии. При ошибке включите исходное приложение и разберитесь с причиной; не удаляйте его том. Помощник отказывается перезаписывать архив, читать symlinks, принимать изменяющиеся файлы и превышать лимиты.

Для автоматизации `--key-stdin` читает ключ из стандартного ввода: существующий менеджер секретов может передать его без аргументов процесса. Это не разрешает копировать целый том работающего сервера. Сначала остановите все процессы, которые пишут в том.

## Проверьте восстановление

Восстанавливайте в новую папку или временный том, не поверх работающей базы:

```sh
docker run --rm -it -v "$PWD/backups:/backup" \
  --entrypoint python "$FMH_IMAGE" /app/bunny/full_backup.py \
  restore /backup/family-full.enc /backup/restored-check
```

Запустите изолированный тестовый экземпляр с прежним соответствующим образом и сохранёнными секретами сервера. Проверьте вход администратора и участника, права библиотек, плейлисты/избранное, письма/воспоминания/вложения, установленные плагины и их состояние. Помощник проверяет аутентичность всего архива до чтения содержимого, отвергает обход путей, links и повторяющиеся имена, затем проверяет SQLite приложения и плагинов. Одна успешная расшифровка не доказывает работу приложения.

Восстановленная папка содержит приватные незашифрованные данные. Защитите её; после приёмки удаляйте только собственную временную копию. Оригинальная музыка и зашифрованный архив должны оставаться нетронутыми. Не отмечайте restore PASS без реального входа в восстановленное приложение.

## Онлайн-копии Bunny и откат

В публичной установке необязательный worker включается через `FMH_BUNNY_BACKUPS=true`, действительные серверные Bunny Storage settings и `BUNNY_BACKUP_KEY_HEX`. Он создаёт и проверяет зашифрованные снимки базы/вложений в разрешённых префиксах. Музыка не удаляется. Retention может чистить только точные имена резервных копий после отдельной проверки восстановления.

Для полной копии облачного тома используйте официальный способ остановки/согласования и чтения тома вашей платформы. Не подменяйте это копированием живого WAL и не придумывайте filesystem/exec API. Если поддерживаемого доступа к тому нет, зафиксируйте ограничение и не утверждайте, что полная копия плагинов/данных создана. До миграции образа нужна свежая проверенная копия фактического состояния приложения.

Откат — это прежний образ **и соответствующие полные данные до обновления**, включая плагины и приватные вложения. Одна смена Docker tag после миграции базы не является проверенным откатом. См. [обновление](updating.md) и [Bunny](deploy/bunny.md).

Проверка целостности SQLite выполняется на временных защищённых копиях базы и её постоянных WAL/journal-файлов. SQLite восстанавливает временный WAL-индекс в копии, не изменяя остановленный исходный том. Это также покрывает завершённые WAL-транзакции при отсутствующем shared-memory индексе.
